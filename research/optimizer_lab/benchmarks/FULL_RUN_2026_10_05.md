# Full #92-descendant GH200 run: timing and validation

**Completed 2026-10-05, seed 0, one GH200.** This is the full schedule of our
single-GPU adaptation, not an exact certified #360 reproduction or an official
8xH100 score.

## Main result

| Measurement | Observed |
|---|---:|
| **Launch-to-exit wall clock** | **870.271 s = 14m 30s** |
| Startup, compilation, graph capture and preflight | 445.534 s = 7m 26s |
| Complete training loop, including data preparation and stalls | 393.046 s = 6m 33s |
| Tail averaging and final mask collection | 0.036 s |
| Full validation, including its data/row reads | 18.975 s |
| Other launch, bookkeeping, graph cleanup and teardown | 12.681 s |
| Training steps / tokens | 1,194 / 328,663,040 |
| Validation tokens | 10,485,760 |
| **Final validation CE** | **3.280118829** |
| Nominal target | 3.28 |
| Difference from nominal target | +0.000118829 |

The loss is very close, but **this single run is slightly above 3.28**. It does not
establish statistical parity with the certified pool. The official criterion is
about a multi-run mean; neither passing nor missing the nominal threshold once
settles it. No trained run was discarded.

All five stages ran, with eight serial microbatches preserving each stage's global
batch size. The full **129.95 GB n-gram table** stayed explicitly bound to Grace CPU
RAM, checked every update cycle and at completion. **No activation checkpointing,
smaller model, smaller hash table or smaller global batch was used.**

## Stage coverage

| Stage | Steps | Global tokens/step | Median inner step |
|---|---:|---:|---:|
| Early | 320 | 131,072 | 131.47 ms |
| Middle | 361 | 262,144 | 235.27 ms |
| Late | 426 | 393,216 | 366.23 ms |
| Taper | 67 | 327,680 | 364.44 ms |
| Extension | 20 | 131,072 | 160.24 ms |

These medians describe the inner global-step timer, **not additive stage runtimes**:
outer-cycle planning, preparation and bookkeeping are excluded, while previously
queued GPU row pulls can overlap the interval. The headline training-loop timer
includes all that work. Use the 393.046-second observation for run comparisons.

The second global step took **41.949 seconds**, far longer than steady state. This
stall is **included**, not subtracted or moved to compilation. We did not collect
a profiler trace that identifies its cause. A future warm-cache repeat may avoid
it, but no such full-run timing has yet been measured.

There were 382 sparse table/value-embedding updates across 383 row-cache cycles.
The final two steps intentionally do not flush a new sparse update, matching the
upstream schedule. Six forward/backward graph configurations passed their forward
replay checks. The extension untied input embeddings from the output head; all
upstream tail averages and norm restoration were applied before final scoring.

Peak PyTorch memory for the whole process, including preflight/evaluation, was
**34.20 GiB allocated / 88.56 GiB reserved**. Reserved allocator memory is not the
live tensor footprint. No global GPU settings were changed or other jobs stopped.

## Comparison with the published record

The certified #92 pool reports **39.914 seconds** on eight H100s and mean validation
CE **3.2773111111**. Our raw training-loop ratio is about **9.85x**, and our one-run
CE is 0.002808 above that pool mean.

**Do not compare 14m30 directly to 39.914 seconds.** The published timer excludes
compilation and validation forward computation, but includes tail finalization
and validation data/row preparation. Our report explicitly includes those costs
in launch-to-exit wall time and reports actual validation separately. Even the
training-only ratio is contextual: source, kernels, reduction order, hardware and
timing boundaries are not identical.

and [source-embedded raw log showing the clock stop before validation forwards](../../../records/track_1_short/2026-08-30_ANVIL2/this_pr/01b2f094-4536-479c-b0dd-cb14eba4844c.txt).

## What ran and what differs

- Source: refactored descendant `4ea6b937337a4889b8cfe3f38a93d120048d8f71`.
  The upstream files are unchanged; a separate research harness adapts execution.
  This descendant's canonical mask, initialization/pruning and sparse-gradient
  storage differ from the certified source.
- Same five-stage token/sequence/window schedule, sampled-softmax candidate counts,
  MTP/prefix objectives, ANVIL rail transition, Adam cadences, embedding untying,
  tail averages, final attention window and 40 original-size validation slices.
- Real FineWeb data: first four training shards; BOS packing is the upstream
  eight-logical-rank algorithm. A one-cycle background thread prepares data and
  candidate IDs **inside the training clock**, unlike the earlier short pilot.
- The CUDA12 ARM FA3 compatibility wrapper pads unequal heads without changing
  the explicit attention scale. It is not the record's mixed-width CUDA13 build.
- Dense gradients are accumulated across eight serial microbatches and averaged.
  Real n-gram gradients accumulate in FP32, cast to BF16 before upstream sparse
  row Adam. This differs from official local/distributed reduction rounding.
- Delayed FP8 amax buffers are shared across the eight microbatches, not eight
  independent ranks. This is another numerical departure, not just infrastructure.
- Validation uses the eager BF16 model path, rather than the record's compiled
  evaluation path. Fusion/intermediate rounding and performance can therefore
  differ; the small loss gap cannot be attributed to the optimizer or offloading
  alone. A compiled-scoring equivalence check remains outstanding.
- The corrected descendant canonical mask is used. No custom validation-token
  selection or reduced validation sample was used.
- The full harness used a fresh Inductor cache directory but reused Triton kernels
  from pilots. **Not fully cold all-cache timing.** No warm-cache full-run repeat.

A preliminary attempt failed during the initial validation preflight because the
initial schedule had not been applied. It ran **zero training steps**, took 15.739
seconds, and was retained separately. The fix preceded the completed run reported
above. No loss result was discarded.

[pilot](TRAINING_SMOKE_2026_10_05.md), at least 200 GiB free host memory, the cached
ARM FA3 binary, and CUDA runtime headers. Set `CUDA_HOME` accordingly, and use local
Inductor/Triton cache directories. Run in a persistent session with a fresh output
directory and retain the shell exit code and launch-to-exit timing.

```bash
python research/optimizer_lab/runners/gh200_record92.py \
  --seed 0 --out /path/to/new-run-directory
```

The default executes the entire 1,194-step schedule and full validation. Shortened
`--limit-steps` runs are diagnostics, not full scores. **No complete checkpoint was
saved**: restarting requires another run; model weights alone would not retain the
130 GB table and its optimizer state.
